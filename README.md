# rammaps

Machine-readable RAM and ROM address maps for retro games, as JSON, one file per game.

The dataset is addresses, offsets, sizes and field names only. It contains no ROM data, graphics, audio, text dumps, decompiled code or save data, and the exporter never reads game-derived text.

## Why this exists

Most of what makes old games fun to revisit lives in their memory: how much EXP a character needs, which chests you already opened, where the party actually is. If that is written down somewhere sensible, people can build companion apps, trackers, accessibility tools, achievement sets and quality-of-life helpers for games they love, without anyone having to start from scratch each time.

This repository is two things at once. It is a small, honest attempt to make that kind of knowledge easier to share. It is also a real-world test of how far careful, local AI tooling can help with reverse engineering: much of the groundwork here was proposed by locally run language models and then checked by hand against our own emulator captures, never taken on trust. We think it is worth being open about that, and about where those tools still fall short.

## Contributing in good faith

Contributions are very welcome, whether that is a single confirmed address or a whole new game. A few things keep this useful and fair for everyone:

- Only add what you have checked yourself, and say how you found it. A short note in `how` is enough. If you are not sure, mark it `unconfirmed`; that is far more helpful than a confident guess.
- Credit the people and projects whose notes pointed you in the right direction, and re-verify their findings rather than copying their tables.
- Never include ROM bytes, graphics, music, game text, decompiled code or save files, and never link to where to get ROMs. This is about facts, not about the games themselves.
- Be kind in issues and reviews. Many of us do this in spare evenings, for games that mattered to us growing up.

See `CONTRIBUTING.md` for the practical details.

## Layout

- `maps/<platform>/<game-slug>.json` the maps. Platform is a lower-case slug (`gba`, `nes`, `snes`, `nds`, `gb`, `gbc`, `n64`, `psx`, ...). The game slug is the lower-kebab-case title plus the region, e.g. `golden-sun-usa`, `golden-sun-the-lost-age-usa`, `fire-emblem-the-sacred-stones-usa`. The filename carries no hash; the ROM SHA-1 is stored inside each file under `rom`.
- `docs/schema.md` the full `rammaps/1` format reference
- `docs/method.md` how entries are found and what the statuses mean
- `schema/rammaps-1.schema.json` JSON Schema for the format
- `scripts/` `validate.py` (checks maps), `gen_index.py` (regenerates the table above), `export_gs1.py` (Golden Sun exporter), see `scripts/README.md`
- `tests/` unit tests for the scripts
- `CONTRIBUTING.md` how to add a map

## Format (`rammaps/1`)

Full reference: `docs/schema.md`. In short:

- `values`: single values. `at` is an absolute address, or `{"ptr": <name in "pointers">, "off": <offset>}` meaning read the 32-bit pointer stored at that address and add the offset. `count` means an array. `type` is u8/s8/u16/s16/u32/s32/u64/s64.
- `structs`: record layouts, field offsets relative to the record start. Field `type` is an integer type or `str` (fixed-length text; only its offset and length are listed, never contents).
- `entities`: arrays of records (`struct`, `at`, `count`).
- `flags`: a story bitfield; flag n is bit n%8 of byte n/8 from `base`.
- `rom_tables`: file offsets and strides of ROM tables (layout only, no contents).
- `sources`: method and acknowledgements.
- Any entry may carry `status` (`confirmed` by default, or `unconfirmed`) and `how` (how it was found).

## Checking and regenerating

- `python3 -I scripts/validate.py maps/*/*.json` validates maps.
- `python3 -I scripts/gen_index.py` regenerates the games table above; `--check` only verifies it.
- `python3 -I -m unittest discover tests` runs the tests.
- Golden Sun only: `python3 -I scripts/export_gs1.py PROFILE.json > maps/gba/golden-sun-usa.json`. The input profile is a JSON file kept by the maintainers; its format is not published yet, so for now the map file itself is the artefact. The script only filters and reformats it.
